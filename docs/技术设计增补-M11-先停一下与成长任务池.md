## 1. 定位与功能清单（合并进 2.4 / 2.5）

两个功能都延续主文档 2.3 的产品原则，并各自新增一条红线。

### F13 先停一下（pause）

- 一句话：情绪上头时，任一方按下暂停，双方进入一段安静的休战期；到点后用一张和好卡把人接回来。
- 谁能用：已绑定双方，任一方都可按，**不需要对方同意**——冷静这件事，不该需要批准。
- 做什么：10 / 30 / 60 分钟三档；期间首页置顶一张牛皮纸便签（发起人 + 剩余时间双方可见）；发起方可提前结束（「我缓好了」）；结束后便签翻面成和好卡，任一方选一句中性话（我刚才有点急 / 晚点再说 / 抱一下），选完卡片消失、首页恢复。
- **产品红线（合并时写进 2.3 原则）**：不存原因、不存次数、不做历史列表、不做任何统计。暂停是刹车不是证据；一旦能翻旧账，这个功能会伤害它想保护的关系。所有接口与页面只暴露「当前这一条」。
- 静音的边界：暂停期间双方「每日提醒」不发送（`runTimer` 跳过，不扣额度、不写 `reminderLastSentDate`）；日记 / 报平安 / 心情 / 纪念日**照常记录**——想记录的温柔不该被拦住，只是不提醒。
- 明确不做（v1）：到点推送「可以回来了」（订阅消息是一次性授权，两人都攒着额度的概率太低，靠卡片与惰性状态判断即可）；「到今晚 0 点」档；暂停原因输入框。

### F14 一起变好（growth，成长任务池）

- 一句话：两个人一起认领一件「一起变好」的事——学一件东西、一起运动、一起存钱、改掉一个坏习惯——有分工，做完一起写收获，自动归档成成长日志；没做成也能用一条复盘体面收尾，**不扣分**。
- 生命周期：A 起草（标题 + 分类 + 建议分工）→ B 认领（确认后任务成立）→ 进行中（分工、标题双方可改）→ 任一方标记完成 → 双方各写一段收获 → 两段都写完，自动归档进成长日志；任意阶段也可发起「复盘」，写清楚问题出在哪，直接归档收尾。
- 收获 / 复盘的解锁规则：**自己写了，才看得到 TA 写的那段**——与日记「次日解锁」同一哲学：先表达，再看回应。对方写了而你还没写时，只显示「TA 写了，你写完就能看」。
- 上限：同时在档（待认领 + 进行中 + 写收获中）≤ 10 件（`GROWTH_LIMIT_REACHED`）；成长日志不设上限、归档后**不可删除**——历史是写完的。
- 明确不做（v1）：积分、排行、连续天数、互相打分（伙伴式恋爱不是 KPI）；每日打卡签到（成长任务是一次性的「完成」，不是 check-in）。

## 2. 数据模型（合并进 5.3 / 5.4 / 5.5）

### 2.1 `pauses`（合并为主文档 5.3.10）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | `p_<16 位 hex>` |
| `coupleId` | string | 是 | 归属，一律从 `ctx` 取 |
| `byOpenid` | string | 是 | 按下的人（双方页面都显示这个身份） |
| `durationMin` | number | 是 | `10` / `30` / `60` |
| `status` | string | 是 | `active` / `ended` / `closed` |
| `startedAt` | Date | 是 | 按下时刻（服务端时间） |
| `endsAt` | Date | 是 | `startedAt + durationMin` 分钟 |
| `endedAt` | Date \| null | 否 | 变为 `ended` 的时刻（到点惰性写，或发起方提前结束） |
| `endChoice` | string \| null | 否 | `hurry`（我刚才有点急）/ `later`（晚点再说）/ `hug`（抱一下）；先选者定 |
| `endChoiceBy` | string \| null | 否 | 选择者 openid |
| `createdAt` | Date | 是 | 同 `startedAt` |
| `updatedAt` | Date | 是 | 最后更新 |

约束：

- 同一 `coupleId` 同时最多一条未 `closed` 的记录：`pause.start` 先查，存在（无论谁按的）→ 幂等返回现状 `existing:true`，不新建；
- 到点是**惰性判断**（读取时 `now >= endsAt` → 视为 `ended` 并写 `endedAt`），不依赖定时任务，与日记解锁 / 纪念日剩余天数的现算思路一致；
- `closed` 文档永久保留（沿用「不物理删除」原则），但**没有任何接口能查历史**；
- 不存原因、不存取消、不存次数——没有字段就没有翻旧账。

### 2.2 `growth_tasks`（合并为主文档 5.3.11）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | `g_<16 位 hex>` |
| `coupleId` | string | 是 | 归属，一律从 `ctx` 取 |
| `createdBy` | string | 是 | 起草者 openid（分工 / 收获 / 复盘存储字段的视角锚点） |
| `title` | string | 是 | 1–30 字 |
| `category` | string | 是 | `learn` / `sport` / `money` / `habit` / `other` |
| `creatorPart` | string | 否 | ≤50 字，创建者承担的部分 |
| `partnerPart` | string | 否 | ≤50 字，**创建者的对方**承担的部分（见下方映射表） |
| `note` | string | 否 | ≤100 字，备注 |
| `status` | string | 是 | `confirming`（待认领）/ `active`（进行中）/ `harvesting`（写收获）/ `archived`（已归档） |
| `archivedType` | string \| null | 否 | `archived` 时必填：`done`（一起完成）/ `reviewed`（复盘收尾） |
| `creatorHarvest` | string \| null | 否 | ≤100 字，创建者的收获 |
| `partnerHarvest` | string \| null | 否 | ≤100 字，创建者的对方的收获 |
| `creatorReview` | string \| null | 否 | ≤100 字，创建者的复盘 |
| `partnerReview` | string \| null | 否 | ≤100 字，创建者的对方的复盘 |
| `createdAt` | Date | 是 | 起草时刻 |
| `confirmedAt` | Date \| null | 否 | 认领时刻 |
| `doneAt` | Date \| null | 否 | 标记完成时刻 |
| `archivedAt` | Date \| null | 否 | 归档时刻 |
| `updatedAt` | Date | 是 | 最后更新 |

**存储 ↔ 出参视角映射**（服务端做，客户端永远只认「我的 / TA 的」）：

| 存储字段 | 含义 | 调用者 = 创建者时的出参 | 调用者 = 对方时的出参 |
| --- | --- | --- | --- |
| `creatorPart` / `creatorHarvest` / `creatorReview` | 创建者的 | `myPart` / `myHarvest` / `myReview` | `partnerPart` / `partnerHarvest` / `partnerReview` |
| `partnerPart` / `partnerHarvest` / `partnerReview` | 创建者的对方的 | `partnerPart` / `partnerHarvest` / `partnerReview` | `myPart` / `myHarvest` / `myReview` |

入参同理：客户端统一传 `myPart` / `partnerPart`（调用者视角），服务端按 `ctx.openid === doc.createdBy` 映射落库。**一个坑**：映射写错方向不会报错、只会把分工写反，`tests/growth.test.js` 必须有「创建者与对方各自改自己视角字段」的两条对向用例锁住。

约束：

- 在档上限：`confirming` + `active` + `harvesting` ≤ 10 件，`growth.add` 先 `count()` 再写，超限 `GROWTH_LIMIT_REACHED`；`archived` 不设上限；
- `archived` 后只允许补写自己的 `harvest`（限 `done`）或 `review`（限 `reviewed`）段落，标题 / 分类 / 分工 / 删除全部锁死（`GROWTH_STATE_INVALID`）；
- 两种收尾互斥：`done` 归档不转复盘、`reviewed` 归档不补收获——同一任务在日志里只能有一种尾巴。

### 2.3 索引（合并进 5.4）

| 集合 | 索引 |
| --- | --- |
| `pauses` | `coupleId`+`status`+`startedAt`（倒序；查「当前这一条」） |
| `growth_tasks` | `coupleId`+`status`+`createdAt`（任务池列表）、`coupleId`+`status`+`archivedAt`（倒序，日志游标） |

### 2.4 状态机（合并进 5.5，新增两节）

#### 暂停 `pauses.status`

```text
active ──到点（惰性）/ end（发起方）──▶ ended ──choose（任一方，先选者定）──▶ closed
```

| 当前 | 事件 | 前置 | 下一状态 | 副作用 |
| --- | --- | --- | --- | --- |
| — | `pause.start` | 已绑定、无未 `closed` 记录、时长枚举合法 | `active` | 写 `byOpenid` / `startedAt` / `endsAt` |
| `active` | `pause.start` | 任一方 | 不变 | 幂等返回现状（`existing:true`），不重复写库 |
| `active` | 读取 | `now >= endsAt` | `ended` | 惰性写 `endedAt`（写失败不阻塞返回） |
| `active` | `pause.end` | 调用者是发起方 | `ended` | 写 `endedAt` |
| `ended` | `pause.end` | 调用者是发起方 | 不变 | 幂等返回 |
| `ended` | `pause.choose` | 任一方、choice 枚举合法 | `closed` | 写 `endChoice` / `endChoiceBy` / `endedAt`（若缺） |
| `closed` | 任意 pause 接口 | — | 不可变 | `pause.status` 返回 `null`（等于没有） |
| 任意 | `pause.end` 非发起方 | — | 不变 | `PAUSE_NOT_OWNER` |
| `active` | `pause.choose` | — | 不变 | `PAUSE_STATE_INVALID`（还没结束，不能选和好话） |

并发保护：`pause.choose` 写前重读，`status` 必须仍为 `ended`；两人同时选只有一个成功，后到者按幂等返回已 `closed` 的结果（先选者定，不报错）。

#### 成长任务 `growth_tasks.status`

```text
confirming ──confirm（对方）──▶ active ──done（任一方）──▶ harvesting ──双方都写收获──▶ archived(done)
     │            │              │
     │            │              └──remove（任一方）──▶ 物理删除
     │            └──confirm（创建者自己）──▶ GROWTH_STATE_INVALID
     └── review（任一方，含 active / harvesting）──────────────▶ archived(reviewed)
```

| 当前 | 事件 | 前置 | 下一状态 | 副作用 |
| --- | --- | --- | --- | --- |
| — | `growth.add` | 已绑定、在档 < 10 | `confirming` | 写 `createdBy` / `createdAt` |
| `confirming` | `growth.confirm` | 调用者**不是**创建者 | `active` | 写 `confirmedAt` |
| `confirming` / `active` | `growth.update` | 任一方 | 不变 | 改标题 / 分类 / 分工 / 备注 |
| `confirming` / `active` / `harvesting` | `growth.remove` | 任一方 | 物理删除 | 不存在时幂等 `removed:false` |
| `active` | `growth.done` | 任一方 | `harvesting` | 写 `doneAt` |
| `harvesting` | `growth.harvest` | 任一方写自己那段 | 不变（双方未齐） | upsert 自己的 harvest |
| `harvesting` | `growth.harvest` | 双方 harvest 均非空 | `archived(done)` | 写 `archivedAt`（自动归档） |
| `archived(done)` | `growth.harvest` | 任一方补写自己那段 | 不变 | 只改自己段落 |
| 非 `archived` | `growth.review` | 任一方 | `archived(reviewed)` | 写自己的 review 段 + `archivedAt` |
| `archived(reviewed)` | `growth.review` | 任一方补写自己那段 | 不变 | 只改自己段落 |
| `archived(done)` | `growth.review` | — | 不变 | `GROWTH_STATE_INVALID`（完成不转复盘） |
| `archived(reviewed)` | `growth.harvest` | — | 不变 | `GROWTH_STATE_INVALID`（复盘不补收获） |

并发保护：`growth.confirm` / `growth.harvest`（触发自动归档的那次）写前重读状态；两人同时写最后两段收获，后到者事务内看到 `archived` 后按补写路径幂等处理，不报错。

## 3. API 契约（合并进 7.17 / 7.18）

统一约定沿用主文档 7.1：鉴权先于入参校验（11.4）、`coupleId` / `openid` 一律从 `ctx` 取、客户端传的一律忽略。以下所有 action 都要求 `ctx.requireBound()`（除注明外），handler 返回纯数据。

### 3.1 先停一下（合并为主文档 7.17）

#### `pause.start`

- 入参：`{ durationMin }`，`10` / `30` / `60`；缺失或非数字 → `INVALID_INPUT`，枚举外 → `PAUSE_DURATION_INVALID`（用户提示「选 10、30 或 60 分钟」）；
- 行为：查当前未 `closed` 记录——存在（无论谁按的）→ 幂等返回 `{ pause, existing: true }`；不存在 → 创建；
- 出参：`{ pause, existing }`。

```json
{
  "pause": {
    "pauseId": "p_9f1c...",
    "byMe": false,
    "byName": "阿泽",
    "durationMin": 30,
    "status": "active",
    "startedAt": "2026-11-18T08:00:00.000Z",
    "endsAt": "2026-11-18T08:30:00.000Z",
    "endChoice": null
  },
  "existing": false
}
```

- `byMe` 让客户端直接渲染「你按的暂停」/「TA 按的暂停」；`byName` 是昵称（脱敏规则同 `home.get`，不返回 openid）。

#### `pause.status`

- 入参：无；
- 行为：返回当前未 `closed` 的一条（含惰性 `ended` 判断与写回）；没有 → `{ pause: null }`；
- 出参：`{ pause }`（结构同上，无 `existing`）。

#### `pause.end`

- 入参：无；
- 行为：发起方提前结束（「我缓好了」）；`active → ended`；已是 `ended` → 幂等返回；无未 `closed` 记录 → `PAUSE_NOT_FOUND`；
- 出参：`{ pause }`。

#### `pause.choose`

- 入参：`{ choice }`，`hurry` / `later` / `hug`；枚举外 → `INVALID_INPUT`；
- 行为：`ended → closed`，先选者定；对 `active` 调 → `PAUSE_STATE_INVALID`；无未 `closed` 记录 → `PAUSE_NOT_FOUND`；
- 出参：`{ pause }`（`status: 'closed'`，`endChoice` 带双方可见的选择；客户端据此收起卡片）。

#### `home.get` 新增 `pause` 区块

走 `lib/home-blocks.js` 的 `optionalBlock`，单块失败降级 `null`（10.3）：

```json
{ "pause": { "byMe": false, "byName": "阿泽", "status": "active", "endsAt": "...", "durationMin": 30, "endChoice": null } }
```

未绑定返回 `"pause": null`。

#### `runTimer` 静音规则（7.15 随动）

- 定时任务逐用户发送前查该用户当前关系是否存在未 `closed` 的 pause：存在 → **整轮跳过该用户**（不发送、不扣额度、不写 `reminderLastSentDate`，下个到点窗口自然重试）；
- 判断只看服务端 `ctx.now`，不引入新时间实现。

### 3.2 一起变好（合并为主文档 7.18）

#### `growth.add`

- 入参：`{ title, category, myPart?, partnerPart?, note? }`
  - `title`：1–30 字，空 → `GROWTH_TITLE_REQUIRED`（「给这件事起个名字」），超长 → `TEXT_TOO_LONG`；
  - `category`：五枚举之一，其它值 → `INVALID_INPUT`；
  - `myPart` / `partnerPart`：≤50 字；`note`：≤100 字；
- 行为：在档（`confirming`+`active`+`harvesting`）≥ 10 → `GROWTH_LIMIT_REACHED`；`title`（scene 3）与 `myPart` / `partnerPart` / `note`（scene 4）写库前过 `security.assertText`；落库 `status: 'confirming'`；
- 出参：`{ task }`。

```json
{
  "task": {
    "taskId": "g_9f1c...",
    "title": "一起背完六级词汇",
    "category": "learn",
    "myPart": "每天中午 30 个",
    "partnerPart": "每天晚上互相抽 20 个",
    "note": "",
    "status": "confirming",
    "createdByMe": true,
    "createdAt": "2026-11-18T09:00:00.000Z"
  }
}
```

#### `growth.confirm`

- 入参：`{ taskId }`；不存在 → `GROWTH_NOT_FOUND`；
- 行为：仅**对方**可认领（创建者确认自己 → `GROWTH_STATE_INVALID`「这件事是你起草的，等 TA 认领」）；`confirming → active`，写 `confirmedAt`；已是 `active` → `GROWTH_STATE_INVALID`；
- 出参：`{ task }`。

#### `growth.update`

- 入参：`{ taskId, title?, category?, myPart?, partnerPart?, note? }`，至少一个字段（全空 → `INVALID_INPUT`）；
- 行为：仅 `confirming` / `active`；文本同样过审；视角映射见 2.2（对向用例锁方向）；
- 出参：`{ task }`。

#### `growth.remove`

- 入参：`{ taskId }`；
- 行为：`confirming` / `active` / `harvesting` 物理删除（客户端先二次确认）；不存在 / 空 id → `removed:false`（幂等）；`archived` → `GROWTH_STATE_INVALID`（「成长日志是写完的历史，不删」）；
- 出参：`{ removed: true }` / `{ removed: false }`。

#### `growth.done`

- 入参：`{ taskId }`；
- 行为：任一方标记完成，`active → harvesting`，写 `doneAt`；`confirming` 直接完成 → `GROWTH_STATE_INVALID`（还没一起认领，谈不上完成）；`harvesting` 再点 → 幂等返回；
- 出参：`{ task }`。

#### `growth.harvest`

- 入参：`{ taskId, text }`，1–100 字，空 → `GROWTH_HARVEST_EMPTY`（「写一句你们做到了什么」），超长 → `TEXT_TOO_LONG`；scene 4 过审；
- 行为：upsert 自己的 harvest 段；在 `harvesting` 且双方 harvest 均非空 → 自动 `archived(done)` 写 `archivedAt`；在 `archived(done)` → 纯补写；在 `confirming` / `active` / `archived(reviewed)` → `GROWTH_STATE_INVALID`；
- 出参：`{ task, archived }`（`archived` 布尔，客户端据此弹「已经收进成长日志」的提示）。

#### `growth.review`

- 入参：`{ taskId, text }`，1–100 字，同上校验与过审；
- 行为：非 `archived` → 直接 `archived(reviewed)` 写自己的 review 段 + `archivedAt`（**不扣分、不追问、不需要对方同意**——复盘是给关系收尾，不是追责）；`archived(reviewed)` → 补写自己那段；`archived(done)` → `GROWTH_STATE_INVALID`；
- 出参：`{ task, archived }`。

#### `growth.list`（任务池）

- 入参：无；
- 查询：`where({ coupleId, status: in [confirming, active, harvesting] })`（在档 ≤ 10，一页放下，不分页）；排序：`confirming` 在前（等人的事最要紧），其余按 `createdAt` 升序；
- 出参：

```json
{
  "items": [
    {
      "taskId": "g_...",
      "title": "一起背完六级词汇",
      "category": "learn",
      "myPart": "每天中午 30 个",
      "partnerPart": "每天晚上互相抽 20 个",
      "note": "",
      "status": "active",
      "createdByMe": true,
      "createdAt": "...",
      "confirmedAt": "...",
      "doneAt": null,
      "myHarvestWritten": false,
      "partnerHarvestWritten": false
    }
  ],
  "stats": { "inFlight": 3, "archivedCount": 12 }
}
```

- 列表只给 `myHarvestWritten` / `partnerHarvestWritten` 布尔（写没写），不给正文——正文只在日志里出现。

## 8. 验收标准（合并进 2.5）

### F13 先停一下

双账号真机走完：

1. A 在首页心情卡下方点「先停一下」选 30 分钟 → **双方**首页顶部出现牛皮纸便签（发起人昵称 + 倒计时），A 显示「我缓好了」、B 不显示；

3. 暂停期间到点的「每日提醒」没有发送、额度未扣、次日正常恢复；
4. 全 app **找不到任何页面**能看到历史暂停、次数或原因；
5. 解绑后：入口消失，`pause.*` 返回 `NOT_BOUND`。

### F14 一起变好

双账号真机走完：

1. A 起草任务（标题 + 分类 + 双方分工）→ B 侧显示「等 TA 认领」→ B 认领后双方一致显示「进行中」；

3. B 点「完成了」→ 双方进入写收获；A 写完看不到 B 的（显示「TA 写了，你写完就能看」），B 也写完 → 自动归档，双方成长日志可见两段收获与「一起完成」chip；

6. 成长卡红点在有待认领任务时出现，认领后消失。

### 9.3 需要用户手动操作（首次部署 M11 前一次性）

与主文档 16.5 / README 的「云开发控制台一次性配置」同源，部署 M11 前补齐；**当前代码未动，不必提前建**（提前建了也不会有数据写入，不影响现有 9 个集合的运行）。

1. **新建 2 个集合**：`pauses`、`growth_tasks`。云函数向不存在的集合写入会直接报错（同 M9 的 `ledger_entries` 先例），**先建集合再部署代码**，否则 `pause.start` / `growth.add` 会失败；
2. **权限**：两个集合都设为「所有用户不可读写」（只允许云函数访问），与其余 9 个集合一致；
3. **索引**（控制台 → 数据库 → 集合 → 索引管理，逐条建）：
   - `pauses`：`coupleId` + `status` + `startedAt`（倒序）——服务「查当前这一条未 closed 的暂停」：`where coupleId + status in [active, ended]`、`startedAt` 倒序取第 1 条；两人数据量极小，一条索引够用；
   - `growth_tasks`：`coupleId` + `status` + `createdAt`（升序）——任务池列表（在档 ≤ 10，一页放下不分页）；
   - `growth_tasks`：`coupleId` + `status` + `archivedAt`（倒序）——成长日志 `growth.log` 的复合游标（`archivedAtISO|_id`，同 `safety_checkins` 的 `createdAt` + `_id` 二级排序先例，同毫秒翻页不丢）；
4. **部署顺序**：先云函数「上传并部署：云端安装依赖」，再上传小程序端。顺序反了，客户端会报「这个操作还不存在」；`config.json` **不需要**新增权限、触发器或环境变量（`runTimer` 静音复用现有 `reminder-tick` 触发器，pause 没有自由文本也不新增订阅模板）；
5. **验证**：两台真机按本文第 8 节走 F13 / F14；不涉及订阅消息模板与 `YIYI_REMINDER_TEMPLATE_ID`。

## 10. 已定决策与预留

已定（实现时不再讨论）：

- pause 无自由文本、不送审；暂停期只静音「每日提醒」，不拦任何记录类操作；
- 和好卡 `hug` 只是文案、不调用任何接口（抱一抱已下线）；暂停不做到点推送；
- 便签不用胶带、不旋转（9.2 既有规则不动）；
- growth 上限 10 在档、日志不删不设限；两种收尾互斥；
- 收获 / 复盘解锁规则：自己写了才见对方的；
- 复盘不需要对方同意、不需要理由字段——写不写问题记录都算体面收尾。
