1. 创建 8 个集合：`users`、`couples`、`bind_invites`、`moods`、`hugs`、`safety_checkins`、`diaries`、`wishes`。
2. 8 个集合权限都设为「所有用户不可读写」。
3. 建索引：
   - `bind_invites`：`creatorOpenid` + `status`；`applicantOpenid` + `status`；`expiresAt`。
   - `couples`：`memberOpenids`（单字段）。
   - `moods`：`coupleId` + `date`（M3）。
   - `hugs`：`coupleId` + `toOpenid` + `status` + `createdAt`（incoming 按 createdAt 倒序取最近一条）；`coupleId` + `fromOpenid` + `createdAt`（M3）。

   - `wishes`：`coupleId` + `done` + `createdAt`；`coupleId` + `createdAt`（M4）。

| 事项 | 现状 | 计划 |
| --- | --- | --- |
| 「同时只有一个活跃邀请 / 一个进行中申请」靠事务外预检 | 极端并发（同一用户双击）可能产生两条记录；正常操作不会 | M6 前改成事务内原子约束（或给 users 加 pendingInviteCode 字段） |
| 取消邀请后停留在 bind 页的邀请步骤 | 文档 8.2 写的是 navigateBack；当前页内回到「生成邀请」更顺 | 以代码为准，后续如需要再改文档 |
| `requireBound` 的接入 | M2 已挂到 ctx 并由 `couple.updateStartDate` 使用 | M3 起每个双人写接口都必须调用 |
| couples 文档丢失等数据异常时自动重置 coupleId | 已记日志 + 重置，避免白屏 | 依赖真人反馈排查 |
| `hug.respond` 的空/非字符串 `hugId` 返回 `HUG_NOT_FOUND` | 文档 11.4 通用入参规则写的是 `INVALID_INPUT`，但 7.7 端错误表未列该码 | 以端错误表（7.7）为准；客户端不会传空值，后续如补 11.4 再统一 |
| `safety.list` 游标改为复合 `createdAtISO|_id` | 文档 7.9 写「nextCursor = 上一页最后一条 createdAt ISO」；纯 ISO 用 `lt` 会在同毫秒记录处永久丢数据、用 `lte` 在整页同毫秒时原地打转，故加 `_id` 兜底（主查询显式 `createdAt desc` + `_id desc` 二级排序，保证同毫秒翻页确定）；客户端按 `checkinId` 去重 | 保留复合游标；如后续要严格按文档，需要契约同时改成复合游标 |
| `safety.checkin` 的 entry 额外返回 `openid` | 文档 7.9 出参示例里没有 `openid`；页面顶部预插入刚报的平安时需要它判断左右对齐。只返回本人 openid，无泄露 | 可保留；若严格对齐文档则改为前端用缓存 user.openid |
| `wish.add` 的 100 条上限是 check-then-write | 先计数再写，极端并发下同对可能短暂超过 100；两人场景概率极低 | 后续可改事务内计数或 `count()` 前置校验 |
| `home.get` 的 `loadWish` 每次读全量（≤100 条） | 只为算 `{total,done,previewTitle}`，仍算 1 次读、未超 9–10 次预算，但返回 payload 偏大 | 后续可改 `count()`×2 + 未完成首条 `limit(1)` |
| `home-blocks.loadSafety` 今日查询未显式 `limit` | 依赖云函数单次 `get` 上限（100 条）；两人同一天理论上限约 288 条，极端连点会被截断导致门灯漏亮。现实操作（10 分钟去重）远达不到 | 可改按 openid 各查最新一条（多 1 次读），或接受当前实现 |
| 技术文档两处笔误 | 16.3 把 `safety.checkin` 出参写成 `checkin`（7.9 是 `entry`）；12.x 写 wishId 空值返回 `INVALID_INPUT`（7.11 端错误表只有 `WISH_NOT_FOUND`/幂等 `removed:false`） | 实现以 7.9 / 7.11 为准，不改用户文档 |
| `hug-banner` 不渲染 `outgoing` 状态 | 8.4 组件表列了 `incoming`/`outgoing` 两个属性，但 9.4 / 10.5 只把「TA 需要抱抱」放在横幅，我发出/已回应/已过期用底部按钮 + 心形动画 | 保留 `outgoing` 属性以兼容 8.4 契约，页面不传；若后续想用横幅表达「TA 抱了你」再打开 |
