## 2. 双人真机验收脚本（14.4）

## 7. 发布流程（14.6）

1. 提交并推送本轮 M6 代码到 `hjj`（`git push origin hjj`），确认远端 HEAD 与本地一致（`git ls-remote origin hjj`）。
2. 本地跑 `node scripts/check-secrets.js`（**需在本机终端**；exit 0 = 通过，exit 2 = 环境不满足（如没有 git），不算通过），并确认 `git ls-files miniprogram/config/env.js` 输出为空。
3. `hjj` 打 tag `v0.1.0` 并推送 tag（此时代码侧 M0–M6 已全部推送，tag 指向 M6 收尾提交）。
4. 云开发控制台部署 `api` 到 dev，接口清单抽查 `system.ping` / `home.get`。
5. 微信开发者工具「上传」体验版，公众平台加 B 为体验成员。
6. 真机跑第 2、3、4 节，修 P0/P1 后重复 4–5。
7. 公众平台配置隐私指引、服务类目、版本描述。
8. 提交审核（正式发布才需要）；通过后先只给 B 用。
9. 观察 1 周，用第 8 节记录反馈。

## 9. 回滚

- 小程序：保留上一个体验版，审核版可回退；
- 云函数：控制台可回滚上一版本；
- 数据库：不做破坏性迁移，新增字段兼容旧数据，回滚不删字段；
- 绑定事务异常：先停新绑定，保留数据，人工核对 `couples`/`users`；
- 回滚后必须重跑 F1–F8 关键路径。
